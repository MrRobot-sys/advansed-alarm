# Advanced Alarm

Будильник для Android, который после звонка **блокирует телефон** и снимает блокировку
только после решения серии алгебраических задач.

Сценарий: **звонок → 30 минут блокировки → 10 задач → полная разблокировка**.

Во время блокировки разрешены только:
* входящие и исходящие звонки (звонилка и экран звонка работают поверх блокировки);
* фонарик;
* камера (запускается с экрана блокировки);
* кнопка «Выключить звонок» — гасит мелодию и вибрацию, но **не снимает блокировку**
  (снять её можно аварийным PIN или решив задачи);
* аварийный PIN из настроек (чтобы не заблокировать телефон навсегда).

> При звонке **без блокировки** (рабочий день или переключатель «звонок без блокировки»)
> та же кнопка называется «Выключить будильник» и снимает будильник полностью.

### Перенос будильника

Во время звонка рядом с кнопкой выключения есть кнопка **«Перенести на N минут»**
(по умолчанию 5). Нажатие гасит мелодию и вибрацию, **отменяет начало блокировки** —
телефон остаётся разблокированным — и планирует повторный звонок через N минут.
Когда будильник зазвонит снова, цикл пойдёт заново: блокировка и задачи.

* Перенос доступен **только пока идёт звонок** (то есть в первые секунды после
  срабатывания). Дальше телефон уже заблокирован, и перенос недоступен.
* Число переносов подряд ограничено (по умолчанию 3) — иначе задачи можно было бы
  откладывать бесконечно. Когда лимит исчерпан, кнопка исчезает.
* Окно для переноса — это длительность звонка. Чтобы успеть решить, увеличьте
  «Длительность звонка» в настройках.
* Перенос переживает перезагрузку телефона: он хранится вместе с будильником,
  а не в памяти.

## Как это работает

### Слои блокировки

| Слой | Что делает | Ограничения |
|------|------------|-------------|
| `LockActivity` | Экран поверх экрана блокировки системы (`showWhenLocked`, `turnScreenOn`, immersive, `excludeFromRecents`) | Кнопку питания перехватить нельзя |
| `AccessibilityGuard` | Служба специальных возможностей: при попытке уйти в другое приложение возвращает экран блокировки, закрывает шторку уведомлений | Службу может отключить только владелец телефона |
| `DeviceAdminReceiver` | `DevicePolicyManager.lockNow()` — системная блокировка (жёсткий режим) | Работает, только если на телефоне уже есть PIN/паттерн/пароль |
| Персистентность | Фаза блокировки и набор задач сохраняются в SharedPreferences | После перезагрузки блокировка восстанавливается |

Кнопку питания перехватить невозможно, а перезагрузка телефона обходит экран блокировки,
поэтому состояние блокировки сохраняется и восстанавливается после загрузки
(`BootReceiver` + полноэкранное уведомление).

Сразу после перезагрузки телефон заблокирован системным PIN, а хранилище приложения
зашифровано (FBE) — ресивер загрузки не может прочитать расписание. Поэтому
восстановление происходит по событию `USER_PRESENT` (пользователь ввёл PIN):
будильники перерегистрируются, а активная блокировка поднимается заново
полноэкранным уведомлением.

### Правила будильников

* Несколько будильников, у каждого — набор дней недели.
* **Окно группировки** (по умолчанию 60 минут): если в этот интервал после будильника
  есть другой включённый будильник *того же дня*, который сам способен запустить
  блокировку, — блокировку запускает **только последний** из них.
* **Рабочие дни без блокировки**: в отмеченные дни недели (по умолчанию выключено)
  будильник только звонит, телефон не блокируется.
* **Звонок без блокировки** — переключатель у отдельного будильника.

### Задачи

Генератор `QuizEngine` выдаёт 10 задач с нарастающей сложностью:

1. линейные уравнения `a·x + b = c`;
2. дроби `(x + k) / m = n` и раскрытие скобок `a(x − k) + b·x = c`;
3. системы двух уравнений;
4. квадратные уравнения (два корня, порядок не важен).

Ответы — целые числа или конечные десятичные дроби. Принимаются `3`, `-2`, `1,75`,
`1.75`, `7/2`. Допуск — `1e-6`.

## Первичная настройка (обязательно)

При первом запуске открывается чеклист:

1. **Служба специальных возможностей** — основной слой защиты.
2. **Администратор устройства** — нужен для жёсткого режима.
3. **Уведомления** — без них не сработает полноэкранное уведомление.
4. **Полноэкранные уведомления** — системная настройка для приложения.
5. **Отключить оптимизацию батареи** — XOS любит убивать фоновые службы.
6. **PIN на телефоне** — обязателен для `lockNow()`.

> Системный PIN телефона приложение **не читает, не меняет и не сбрасывает**.
> Оно только вызывает `lockNow()` у администратора устройства.

## Настройки

| Параметр | По умолчанию | Смысл |
|----------|--------------|-------|
| Блокировка после звонка, мин | 30 | Длительность блокировки |
| Количество задач | 10 | Сколько задач нужно решить |
| Окно группировки, мин | 60 | Правило «последнего будильника» |
| Длительность звонка, сек | 60 | Сколько звучит мелодия |
| Перенос будильника, мин | 5 | На сколько минут откладывает кнопка «Перенести» |
| Максимум переносов подряд | 3 | 0 — без ограничения |
| Аварийный PIN | 1234 | Выход из блокировки |
| Жёсткий режим | выкл | Дополнительно вызывает `lockNow()` |
| Рабочие дни без блокировки | пусто | Дни, когда телефон не блокируется |
| Разрешённые приложения | пусто | Дополнительные пакеты сверх системных |

### Про жёсткий режим

`lockNow()` поднимает **системный** экран блокировки поверх нашего экрана.
Пока он поднят, камера (обычная Activity) оказывается под ним и пользователь её не видит.
Поэтому жёсткий режим по умолчанию выключен: требование «во время блокировки работает
камера» выполняется именно в обычном режиме, где блокировку держит наш экран
и служба специальных возможностей.

## Проверка на устройстве

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb logcat -s LockController:* AccessibilityGuard:* AlarmService:*
```

Кнопка **«Проверить блокировку (1 минута)»** на главном экране запускает полный
цикл: звонок → минута блокировки → задачи → разблокировка, без ожидания будильника.

### Что проверено на реальном устройстве

Проверено на Infinix Hot 60 Pro (Android 16, XOS 16.3) — реальные будильники,
а не только кнопка теста:

* будильник зарегистрирован в `AlarmManager` как `RTC_WAKEUP` с `window=0`
  (точный) и `exactAllowReason=policy_permission`; `setAlarmClock` показывает
  ближайший будильник в статусной строке;
* по срабатыванию поднимается `LockActivity`, сервис уходит в foreground
  (`types=mediaPlayback`, категория `alarm`);
* фазы идут в порядке **звонок → блокировка (с отсчётом) → задачи**;
* переход в другие приложения, в том числе по кнопке «Домой», отбивается
  службой специальных возможностей; возврат из камеры — тоже;
* фонарик включается, камера открывается поверх блокировки;
* задачи проверяются: верный ответ переключает на следующий, неверный —
  не переключает;
* аварийный PIN снимает блокировку и очищает состояние;
* **правило группировки**: из двух будильников в пределах окна блокирует только
  последний (первый звонит без блокировки);
* **перенос будильника**: рядом с кнопкой выключения есть «Перенести на N минут»;
  нажатие гасит звонок, **снимает начавшуюся блокировку** (телефон остаётся
  разблокированным) и планирует повторный звонок ровно через N минут — проверено
  по `AlarmManager` (`window=0`) и по факту повторного звонка;
* **лимит переносов**: после трёх переносов подряд кнопка «Перенести» исчезает,
  остаётся только выключение звонка;
* **после перезагрузки** блокировка, таймер и расписание восстанавливаются.

## Ограничения (честно)

* **Кнопку питания перехватить нельзя.** Отключение экрана вернёт экран блокировки,
  но выключить телефон намертво нельзя.
* **Перенос доступен только во время звонка.** Когда звонок уже погашен и телефон
  заблокирован, отложить будильник нельзя — перенос не восстанавливает уже начавшуюся
  блокировку. У тестовой кнопки «Проверить блокировку (1 минута)» кнопки переноса нет:
  там нет будильника в хранилище, переносить нечего.
* **Перенос переживает перезагрузку**, но сбрасывается, если выключить будильник
  или изменить его расписание.
* **Перезагрузка** — единственный способ полностью сбросить блокировку. Состояние
  восстанавливается после разблокировки телефона (нужен системный PIN: без него
  приложение не может прочитать своё зашифрованное хранилище).
* **Службу специальных возможностей Android отключает сам** при переустановке
  приложения и при `adb shell am force-stop` — после этого её нужно включить
  заново (Настройки → Специальные возможности). Обычная установка из магазина
  этого не делает, но `adb install -r` — делает.
* **Отключение службы специальных возможностей** делает блокировку существенно слабее
  (остаётся только экран LockActivity).
* `setKeyguardDisabledFeatures` и `KEYGUARD_DISABLE_UNLOCK` доступны только
  Device/Profile Owner, поэтому не используются.
* `resetPassword` не используется — системный PIN телефона не затрагивается.
